XADD · XREADGROUP · XAUTOCLAIM

一次修复的数据流

  1. 01 / COMMITAPI → PostgreSQL

    同事务保存 Task、Run、Intent 与初始事件，返回 202。

  2. 02 / PUBLISHIntent → Redis Stream

    Worker 扫描到期意图，只投递 intent_id。

  3. 03 / CLAIMStream → Worker → PostgreSQL

    消费组交付消息，Worker 按 ID 取得数据库租约。

  4. 04 / EXECUTEWorker → Runtime

    原 Open SWE Agent 修改固定提交上的工作区。

  5. 05 / VERIFYPatch → Validator → PostgreSQL

    保存不可变补丁，在干净检出中验证并写回结果。

Agent checkout→Immutable patch + SHA-256→Fresh Validator checkout

PostgreSQL 是任务与派发状态的事实来源；Redis 只交付消息。Backend 与 Worker 共享本地工作卷，LangGraph Runtime 保存 Agent 执行状态。

故障发生时如何继续

发布失败Intent 留在数据库，下轮重试 XADD。

重复投递数据库行锁与租约只允许一个 Worker 领取。

消费后崩溃待确认消息经 XAUTOCLAIM 接管。

取得租约后崩溃租约到期后对账 Runtime 执行身份。

Stream 丢失从 PostgreSQL 的待处理 Intent 重建消息。

TASK / RUN

关联执行身份与事件

保存用户归属、输入参数、任务状态和 deadline，关联 thread 与 Runtime Run，按顺序记录派发、执行、验证与完成事件。

PATCH / HASH

持久保存不可变补丁

候选记录包含精确 base commit、原始 patch 字节、SHA-256 和修改文件列表，支持下载与独立 checkout 重放。

CHECKS / LOGS

逐项保存验证结果

记录 baseline、patch check/apply、target 与 regression 的退出码、输出、耗时和超时信息，按需加载到详情页。

05 / RUN THE SYSTEM

运行修复系统。

从仓库根目录启动 PostgreSQL、Redis、Backend、Worker 与 Dashboard 五个服务。内置 arithmetic 示例使用确定性模型执行完整修复链。需要 Docker Compose v2 和 Python 3.9+。
